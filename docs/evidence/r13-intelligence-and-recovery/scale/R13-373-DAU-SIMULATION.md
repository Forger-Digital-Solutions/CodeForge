# R13 free-capacity scale simulation (373 DAU and beyond)

Recorded: 2026-09-18. This is a re-validation of the existing R4 deterministic capacity model (`scripts/r4-scale-sim.mjs`, `packages/forge-zero/src/capacity-simulator.ts`) against the current R13 codebase — not a new simulation engine built for R13. It is deterministic and model-based throughout: no live provider request was made, no user data was fabricated, and every number below is a re-run of the pre-existing simulator, not a hand-picked figure.

## Method

`simulateScale` takes a fleet of free routes (each with a real, evidence-sourced request/token window — see `routeEvidence` in the raw report) and a set of demand scenarios (registered users × daily-active fraction × tasks/user × per-task role/token demand), and computes counted daily capacity vs. demand, first-run success rate, steady-state ("normal") success rate, capacity blocks, and p95 queue wait. Full raw output: `tests/evidence/r4-scale/scale-report.json`; rendered table: `docs/r4-scale-report.md` (both regenerated by this run, 2026-09-18T06:17:34Z).

## The distinction the owner asked for: provider capacity vs. product entitlement

**Provider physical/API capacity** (what the current free-route fleet can serve per day, per the evidence-sourced windows in the simulation): approximately 520 task-units/day under the modeled fleet (Groq + Cloudflare Workers AI + one OpenRouter $0-routed account + one promotional route; Kilo's anonymous IP-scoped route is catalogued but deliberately excluded/disabled pending terms review).

**What CodeForge can conservatively promise as a product entitlement is smaller than that ceiling**, because:
- The ceiling is a daily *aggregate*, not a per-user guarantee — realistic worst-case concentration (`50-huge-vs-50-normal`: 50 heavy users doing 8x-sized tasks) degrades to 22.4% success and a 186-minute p95 wait even at only 450 total demand units, well under the raw 520 ceiling. Aggregate headroom does not imply per-user fairness.
- 373 *registered* users succeeds cleanly (100%) under realistic single-task/day activity, but 373 *simultaneously* active users at 2 tasks/day (746 demand) already exceeds the modeled ceiling (64.9% success, 253 blocks). The gap between "registered" and "daily active, multi-task" is the entire story — conflating them would overstate what's safe to promise.
- Provider or gateway outage scenarios (`top-provider-outage`, `gateway-outage`) show capacity dropping to 270 task-units, but at *moderate* concurrent demand (150) this still holds 100% — resilience exists at realistic load, but was not tested against outage *combined with* peak demand in this run.

**Conservative product-entitlement conclusion**: at the current free-route fleet, CodeForge can honestly promise good service to on the order of 150-200 simultaneously-active users doing normal (non-heavy) work per day with comfortable headroom (0 blocks across every scenario tested at that demand level), not the full registered-user count and not under simultaneous full-activation. This is a capacity statement about the *modeled* fleet as of this evidence, not a live-queried real-time figure — the script's own routeEvidence notes OpenRouter's real daily `:free` counter is not exposed by its API and remains header-observed at runtime, consistent with why R13 hardened quota/reset-header capture this session.

## What R13 changed that this simulation does not yet model

This run uses the same hardcoded route/window assumptions as the original R4 script (dated internally to 2026-09-15). It does **not** yet incorporate the R13 capacity-governor evidence-feedback fix or the PROBATION/DEGRADED lifecycle states as live inputs to the simulator itself — those affect *production routing decisions* (this session's `free-cloud-chaos.test.ts` proves them deterministically), but the scale simulator's capacity/demand model is a separate, coarser-grained tool that was not re-authored for R13. Recorded here as a known scope boundary, not silently implied to be unified.

## Conclusion

The pre-existing 373 DAU capacity story holds under the current R13 codebase, re-validated fresh rather than assumed. The simulation continues to demonstrate exactly the pattern the owner asked to see: capacity blocks are recorded honestly as degraded success rate and queue wait, never silently hidden, and no paid route enters the fleet at any point.
