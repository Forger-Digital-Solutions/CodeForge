# R58 watchdog and continuation decision

R57's coder lease had a 600-second base and two 120-second extensions. A healthy route could therefore be stopped after 840 seconds even though the coder still had useful turns left. R58 retains the 600-second base and 120-second observation window. A coder can earn up to 15 extensions, with an absolute 2,400-second lease bound. Explorer and planner phase ceilings remain independent; other workers retain the two-extension default.

Extensions require a new distinct successful tool effect in the bounded agent journal trace. New file observations, changed observations, and distinct successful edits count. Repeated reads, identical command output, failed or denied calls, and model turns by themselves do not count. The existing coder anti-loop classifier and its model/tool budgets remain active. Two consecutive checks without new useful evidence stop a worker as `stalled`; reaching the extension or absolute bound while still advancing records `watchdog_budget_ceiling`. Parent cancellation interrupts either case.

Each durable model-turn record now carries its measured provider-response latency. The coder's permitted extension count is bounded by its 25-turn budget, observed mean latency, a 1.5 overhead factor, and the 15-extension hard limit. This changes the lease envelope for slow healthy routes without granting time for activity alone. The worker record persists executor kind, useful-progress count, duplicate-progress checks, observed mean model latency, extension count, and abort reason. It stores hashes and counts rather than prompt text.

On a productive coder lease ceiling, the orchestrator awaits the terminal child, creates an immutable Git checkpoint of the same isolated worktree, records the prior worker and checkpoint, then grants at most one sequential continuation lease. The new worker receives the original goal, task plan, changed-file inventory, prior status, and verification commands. Existing edits remain in the worktree. The final result still passes the independent reviewer, verifier, and `evaluateCompletion` gate. The continuation is never granted for a stall, loop, cancellation, or worker without useful progress.

The absolute coder execution bound is two 2,400-second leases in one orchestrator run. Existing model-turn and tool-call budgets also bound each lease. A process crash during the new continuation is handled by the existing recovery classification and revalidation path; automatic restart of a terminal budget-expired parent run across process restarts is not established by R58.

The desktop explicitly enables R1 subagents. The server defaults to R1 and permits an explicit compatibility override. An R1 worker without a real agent runtime fails closed. The orchestrator cannot turn a directory listing into a coder result, and the direct runtime compatibility path requires a completed coder result with its actual changed-file list.
