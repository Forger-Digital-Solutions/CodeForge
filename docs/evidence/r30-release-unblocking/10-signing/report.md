# R30 Windows distribution trust

The read-only [baseline audit](baseline.json) inspected the retained R29 unpacked executable, NSIS installer, and portable executable. Windows Authenticode reported `NotSigned` for all three. No Code Signing EKU identity was present in the inspected current-user or local-machine certificate stores, and no signing environment variable was configured in this process. At the R29 handoff, the `windows-desktop` workflow built and uploaded Windows artifacts without a signing or timestamp step.

The code-signing gate remains **blocked**. The fresh R30 unpacked executable, portable executable, and NSIS installer all report `NotSigned` in the [artifact receipt](../14-release-artifacts/artifacts.json). The owner boundary is a trusted production Authenticode identity and CI secret/configuration provisioned by the project owner; a self-signed or test certificate would not close this gate. The R30 Windows tag workflow now requires signing credentials, signs and timestamps release artifacts through electron-builder, and runs `scripts/verify-windows-signatures.ps1` to require valid Authenticode and timestamps before upload. This positive path has not run with a production certificate. Once supplied, execute the tag workflow, inspect the final signer chain and signature status with `Get-AuthenticodeSignature`, and freeze hashes only after signing. No certificate was purchased or fabricated in R30.

The new `scripts/verify-windows-signatures.ps1` gate was exercised against the retained unsigned artifacts and rejected them as expected; the [negative receipt](gate-negative.json) records that result.
