# R30 second Windows hardware

Only the current Windows host was accessible in this task. The [current-host receipt](current-host.json) records OS, CPU, logical processors, and memory through Windows and Node; the WMI GPU query returned no data in this command environment. No second physical Windows installation, different GPU, DPI setup, or installer run on another machine was observed. This gate remains **blocked by access to a second host**.

The repository already has `.github/workflows/release-consumer-acceptance.yml`, which consumes published release bytes on `windows-2025` and checks hashes, installer behavior, packaged smoke, persistence, and uninstall. R30 artifacts were not published or pushed, so that workflow cannot be counted as R30 proof. Once an R30 candidate is made available to an authorized second host, record its CPU/GPU/Windows build and display scale; verify the artifact SHA-256; install; sign in with a test account; open a disposable repository; execute a coding task and terminal command; run `full`, `interrupt`, and `recover` packaged smoke; close/reopen and verify persistence; then test uninstall or upgrade. Preserve the raw receipts and compare them with the current-host hashes. Until those steps execute, no portability claim is made.
