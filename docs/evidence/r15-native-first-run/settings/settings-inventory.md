# R15 Settings Inventory

## Method and scope

Source trace completed on 2026-09-18 against `d0f94847d4a029e0f336022bd252bff12e6712b9` plus the
uncommitted R15 remediation in this working tree. Every entry point in
`apps/desktop/src/renderer/settings/settings-registry.tsx` and every mutable control in the
rendered sections was traced through its IPC/client call, persistence location, and runtime
consumer. Repeated provider/model cards are generated by one shared component; their row below
applies to every dynamically returned provider or model, not a sample.

Read-only facts and deliberately unavailable features are inventoried too. They are not user

## Persistence and failure behavior

R15 now treats `false` from the atomic trusted settings writer as a failed setting mutation. The
canonical app settings, close behavior, recent-project clear, provider credential writes, cloud
session writes, provider policy/attestation writes, and first-run acknowledgement now return a
readable failure instead of silently reporting success. Runtime-backed privacy/indexing changes
are applied by the control plane before their preference is persisted; a non-2xx or unreachable
runtime leaves the prior persisted preference in place and produces an in-app Settings alert.

## Deliberately absent controls

There is no user-facing switch for ForgeZero, completion verification, security boundaries,
browser automation, MCP, GEMS access, paid auto, local models, telemetry, automatic updates, or
Windows autostart. Where a capability is unavailable, the UI shows a fact/availability state rather
than an inert toggle.

## Native-test state

Source and focused regression tests are complete. Installed-app persistence and Settings navigation
are still pending the newly built installer smoke, so this document is an implementation inventory,
not Settings certification.
