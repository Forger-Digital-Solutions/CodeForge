## Architecture and storage

`ConnectedAccounts` is a trusted desktop-host service over the existing encrypted credential host and owner-scoped settings. A stable internal UUID identifies each connection; provider name alone is never unique. Each connection keeps provider/account metadata, authentication method, credential reference/fingerprint, current catalog/entitlement observations, enabled state, label, routing preference and independent paid permission/budget. Public DTOs contain masked identity and status, never credential reference, fingerprint, raw owner/account identity or secret. No schema migration or credential duplication in a second database is required: the existing host settings/secret references and R55 session-backed registry are extended.

Different valid connections coexist. Exact duplicate credentials resolve to the existing connection; reauthorization/replacement does not manufacture another allowance. Credentials use deterministic owner-and-connection references under the existing secure-key allowlist. Atomic failures roll back new secret writes; owner changes across awaited work reject stale results. Startup retains connection metadata/credential storage but requires a current authoritative recheck before any account dispatch. Independent disable, local disconnect, replacement and reauthorization withdraw the affected connection without provider-global overwrite. Credential replacement resets paid permission.

OpenRouter uses the existing official browser PKCE/S256/callback exchange, with redirect rejection on the exchange. The provider's current documented top-level `state` parameter is now used and validated (the former state-in-`callback_url` form was incompatible); explicit consent denial is handled without key exchange. Native callback tests pass 19/19 with loopback authorization. No undocumented refresh token is assumed. Credential validity and connection admission are separate from unpaid Free certification: valid PAID metadata permits connection while default spending/Free credential access remain off. Paid/expired/provisioning/management and ambiguous entitlement checks retain their proper distinct outcomes. Local disconnect is local secret deletion; no unsupported remote management-key revocation call is invented. [Current provider flow](https://openrouter.ai/docs/guides/overview/auth/oauth).

Groq uses supported API-key entry through encrypted storage; documented delegated OAuth was not established. Other existing optional provider definitions/adapters are reused, with no blanket OAuth claim or automatic Free certificate. Multiple keys/projects do not imply independent organizations or permissions. Provider terms govern which legitimate external accounts/workspaces may be connected.

## Eligibility and accounting

Connection permission is separate from physical quota ownership. Canonical provider plus evidenced external account/organization/IP identity remains the quota key; connection aliases, keys and users cannot multiply it. Unknown ownership is conservatively shared provider scope. Personal Free projections do not sum duplicate remaining allowance observations for a shared domain.

Typed R55 user sources carry exact canonical provider/model qualification receipts and stable connection identity. Only current QUALIFIED roles are admitted; Reviewer requires the measured current protocol. No Planner/Tester/Lead/Tool Agent competence is inferred from unrelated role success. Exact credentials, fingerprint, owner, provider/account freshness and pricing are rechecked immediately before execution. Free routes retain ForgeZero and normal fabric/privacy/capacity/health admission.

Default routing is FreeOnly. The UI supports FreePreferred/PaidFallback, PaidPreferred, SpecificAccount and AutoBest settings, but stored preference is not runtime dispatch authority. Optional paid execution requires global paid permission, explicit consent, limitations acknowledgement, per-connection permission, a finite monthly budget, current authoritative USD token-only prices without unknown ancillary fees and bounded output tokens. Current mixed-mode runtime/guard/transport checks pass in the final 393-case affected receipt; no live paid routing is claimed. Managed Paid is a future separate category, not a provisioned subscription.

Current production role-runtime fixtures prove default Free selection, explicit paid preference, Free-only exclusion, exact connection selection, Manual-account isolation and Auto Best measured-role comparison. Common workflow/subagent execution resolves the same trusted host allowance. Parent-authorized workspace stamps allow isolated children to retain the intended inference privacy context without changing tool confinement; dispatch rechecks current host owner/workspace.

Paid model role qualification now uses an explicit, bounded Explorer/Reviewer workflow for an exact model. It reserves each request through the same per-connection budget guard, requires current paid permission and exact authoritative prices, and stores a paid-class receipt without changing Free evidence. A visible main-process estimate must be presented and acknowledged before the provider wire request; unavailable or stale presentation fails closed. These paths passed focused unit/integration tests, but no new paid qualification or paid inference was run against a real provider account. Parent recovery now persists owner and roster-policy identity, re-resolves current workspace/privacy/permissions, parks missing authority, and retries only through the explicit current-authority recovery path. The prior real-process scripted account fixture retains 13/13 checks, but live paid/reviewer model continuation remains unproved. The local cost estimate and budget are not a provider invoice cap.

The durable ledger reserves an upper estimate before physical dispatch, keeps unique request IDs and connection-local UTC-month accounting, and rejects replay. Physical account/organization concurrency and structured 429 cooldown are shared across connections. Predispatch cancellation can release a reservation; uncertain postdispatch outcomes/crash holds remain conservative. Unexpected charges block output and subsequent account admission. Exact served-model validation, complete stream and accounting settlement precede executable tool release. Reported chat/SSE cost reaches the ledger, and unrepresentable charges retain reported USD plus accounting uncertainty and a conservative blocked numeric floor. Local estimates and budgets are not an upstream invoice guarantee; main/UI disclosure states this limitation explicitly.

## Official provider constraints

OpenRouter official PKCE, current key identity and spend controls support the implemented connection distinction. Its terms restrict one individual creating multiple accounts, and extra accounts/keys do not multiply globally governed limits. CodeForge supports legitimate authorized connections/workspaces without creating identities or cycling quota. [OAuth](https://openrouter.ai/docs/guides/overview/auth/oauth), [key metadata](https://openrouter.ai/docs/api/api-reference/api-keys/get-current-api-key), [limits](https://openrouter.ai/docs/api_reference/limits), [terms](https://openrouter.ai/terms), [spend controls](https://openrouter.ai/docs/guides/best-practices/spend-controls).

Groq's official project/key organization limits and delayed spend enforcement do not establish delegated OAuth or exact invoice protection. Its optional keys remain owner-authorized connections, with unknown entitlement/pricing failing closed for automatic execution. [Security](https://console.groq.com/docs/production-readiness/security-onboarding), [projects](https://console.groq.com/docs/projects), [limits](https://console.groq.com/docs/rate-limits), [spend controls](https://console.groq.com/docs/spend-limits).
