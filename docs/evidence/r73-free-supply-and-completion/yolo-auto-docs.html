OpenAI-Compatible API Endpoints

Use base URL https://yolo-auto.com/v1 and send Authorization: Bearer yolo_YOUR_KEY. Yolo-Auto implements a focused OpenAI-compatible surface rather than every OpenAI API route.

GET /v1/modelsList available public model IDs with the plan-bounded context window and the thinking levels each model accepts.
POST /v1/chat/completionsSend messages and create a normal or streaming chat completion.
GET /v1/usageRead request, token, and quota metadata for the authenticated API key.

Use the request examples below to verify the endpoint, API key, model ID, JSON body, and streaming behavior before configuring a third-party client.

Request format and limits

qwen3.8-flash supports text, images, and tools, as does yolo while backed by Flash. Chat completion request bodies may contain up to 20 MB of JSON.

Existing clients explicitly configured for qwen3.8-27b remain supported, including their image input capability. Check GET /v1/models with your key for access.

Capacity and retries

Paid plans have fixed monthly prices with no per-token overage fees. Fair use, bounded project queues, and shared-capacity availability apply.

Build clients for transient capacity responses. Requests that exceed your plan allowance return HTTP 429 immediately. Honor Retry-After before retrying. Your subscription price does not change.

When your project is at capacity, requests within the plan allowance can wait in a bounded project queue. A full queue or an expired wait returns HTTP 429.

Admitted requests remain subject to inference capacity and timeouts; admission does not guarantee immediate model execution.

Client guidance

  • Reduce request volume when requests queue or return HTTP 429.
  • Cancel abandoned requests and streams promptly.
  • Honor Retry-After on HTTP 429 responses and retry with jitter.
  • Do not submit duplicate work while the original request is queued or in progress.

oh-my-pi (omp)Preferred harness

Preferred harness. Registered Yolo-Auto provider plus a plan-first todo-discipline extension.

Yolo-Auto is a registered provider in oh-my-pi. Sign in with your API key once and omp discovers the live model list from GET /v1/models. No provider block, no models.yml entry.

1. Install omp

# macOS / Linux
curl -fsSL https://omp.sh/install | sh

# Windows (PowerShell)
irm https://omp.sh/install.ps1 | iex

2. Register Yolo-Auto

Create a key at yolo-auto.com/app, then attach it to omp. After discovery, select a model with /model or --model.

# Start omp and register the provider (paste your yolo_... key when prompted).
omp
/login yolo-auto

# Or provide the key non-interactively; omp reads it from the environment.
export YOLO_AUTO_API_KEY="yolo_YOUR_KEY_HERE"   # Windows PowerShell: setx YOLO_AUTO_API_KEY "yolo_YOUR_KEY_HERE"

# Confirm discovery of the live model list, then select the model.
omp models yolo-auto
omp --model yolo-auto/qwen3.8-flash

# Optional: make it the session default in ~/.omp/agent/config.yml
modelRoles:
  default: yolo-auto/qwen3.8-flash

3. Recommended: plan-first todo discipline

The yolo-auto/yolo auto-router model performs best with plan-first todo lists. This official extension enforces that ordering: the first non-todo tool call of each request is blocked once with an instruction to commit a plan, and a short per-model addendum rides the system prompt. Other models are untouched; subagent sessions never arm. Full guide: yolo-todo-discipline-setup.md · repo: https://github.com/yolo-auto-org/yolo-auto-omp.

# macOS / Linux
mkdir -p ~/.omp/agent/extensions
curl -fsSL https://raw.githubusercontent.com/yolo-auto-org/yolo-auto-omp/main/yolo-todo-discipline.ts -o ~/.omp/agent/extensions/yolo-todo-discipline.ts

# Windows (PowerShell)
New-Item -ItemType Directory -Force "$env:USERPROFILE\.omp\agent\extensions" | Out-Null
curl.exe -fsSL https://raw.githubusercontent.com/yolo-auto-org/yolo-auto-omp/main/yolo-todo-discipline.ts -o "$env:USERPROFILE\.omp\agent\extensions\yolo-todo-discipline.ts"

# Then start a new omp session (/new or relaunch). Extensions load at session start.

Claude Code

Bridge through LiteLLM's Anthropic-compatible endpoint.

Claude Code expects Anthropic Messages API. Use LiteLLM as a local bridge to Yolo-Auto's OpenAI-compatible endpoint.

1. Save this as litellm-yolo-auto.yaml

model_list:
  - model_name: qwen3.8-flash
    litellm_params:
      model: openai/qwen3.8-flash
      api_key: os.environ/YOLO_AUTO_API_KEY
      api_base: https://yolo-auto.com/v1

litellm_settings:
  master_key: os.environ/LITELLM_MASTER_KEY

2. Start the bridge and launch Claude Code

# Install LiteLLM proxy support
uv tool install 'litellm[proxy]'

# Set secrets locally. Use your real yolo_ key and generate your own proxy key.
export YOLO_AUTO_API_KEY="YOUR_yolo_API_KEY_HERE"
export LITELLM_MASTER_KEY="sk-local-proxy-key-change-me"

# Start the Anthropic-compatible bridge. Save the YAML above as litellm-yolo-auto.yaml first.
litellm --config ./litellm-yolo-auto.yaml --host 127.0.0.1 --port 4000

# In another shell, point Claude Code at LiteLLM's Anthropic Messages API bridge.
export ANTHROPIC_BASE_URL="http://127.0.0.1:4000"
export ANTHROPIC_AUTH_TOKEN="$LITELLM_MASTER_KEY"
export CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1
claude --model qwen3.8-flash

Request examples

List models

Each entry reports context_length and max_model_len for the window your plan allows on that model, and thinking with the accepted reasoning levels when the model supports them. Configure client context windows from this response instead of a bundled model catalog, which can overstate the window your plan enforces.

curl https://yolo-auto.com/v1/models \
  -H "Authorization: Bearer yolo_YOUR_KEY"

Chat completion

Streaming is recommended for long-context or long-output requests. When the upstream starts the response promptly, streaming reduces the risk of hitting the proxied read deadline before inference finishes.

curl https://yolo-auto.com/v1/chat/completions \
  -H "Authorization: Bearer yolo_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3.8-flash",
    "messages": [
      { "role": "user", "content": "Hello from Yolo-Auto" }
    ],
    "stream": true
  }'

curl https://yolo-auto.com/v1/usage \
