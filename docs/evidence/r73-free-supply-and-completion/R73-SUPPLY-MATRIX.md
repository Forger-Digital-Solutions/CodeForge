## Production controls and validation

The adapter uses the pinned public canonical endpoint and rejects redirects/payment challenges. Expired catalog evidence refreshes before inference; a removed model cannot continue. Semantically distinct exact-model identity is required for chat and every stream. Executable streamed tool calls are withheld until the checked stream ends, preventing a later substituted usage frame from releasing an edit. Narrow witnessed malformed-tool diagnostics classify as INVALID_TOOL_OUTPUT and do not cool the IP quota domain; actual FREE_TIER_RATE_LIMITED applies to the whole shared source-IP domain.

BlockRun has its own hashed terms/privacy/price policy receipt, reverified every6hours, expiring after7days. Changed terms fail closed and cannot inherit Kilo's receipt. Public-code consent is required; no private repository content was transmitted or certified. Unknown upstream retention/training and shared upstream quotas remain unknown.

Focused validation checkpoint: **79tests/8files passed**, including the new Reviewer-only receipt helper and capability-aware default qualification, BlockRun transport, existing Kilo and stream-error regressions, and registry policy/quota isolation. Providers/model-registry TypeScript project builds passed. Desktop/workspace packaging and final regression evidence are reported separately. No local LLM, CPU training, new router, arbitrary user ceiling or proxy/account quota evasion was introduced.

Public-source snapshots are indexed in supply-research.json and additional-supply-research.json; those GET-only research scripts spent zero inference calls. Historical and failed receipts remain preserved.

## Installed runtime and hosted dispatch scope

The new BlockRun route is integrated into the installed desktop and local `forge serve`/CLI path through the existing FreeCloudService, ForgeZero and Eight-Bit fabric. This does **not** certify BlockRun for the hosted cloud workflow's authenticated client-direct outbox. That existing remote chain remains Kilo-only: signed provider/endpoint assignments, durable job dispatch, worker factory, feedback schema, cloud admission and cloud supply initialization all restrict Kilo. Desktop settings report the installed runtime's connections; they do not establish hosted BlockRun availability.

Remote BlockRun enablement would require a coordinated extension of that same protocol, including provider identity in durable jobs and signed assignments, provider-specific policy/catalog/role checks at dispatch, exact served-model validation before tool proposals, and quota-owner feedback isolation. The R73 addition does not widen those security boundaries or introduce another router. No hosted BlockRun inference, cloud deployment or remote capability claim is made.
