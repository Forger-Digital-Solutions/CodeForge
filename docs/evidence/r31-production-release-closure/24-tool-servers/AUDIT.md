# R31 MCP / Tool Servers Audit

Implementation: `packages/mcp` — `GovernedMcpClient` on the official `@modelcontextprotocol/sdk`
(stdio JSON-RPC + streamable-HTTP transports) behind `McpRegistry`.

Real lifecycle evidence: `mcp-lifecycle.json` (generated by
`benchmarks/r31/mcp-lifecycle-evidence.mjs` over `packages/mcp/test/fixtures/mcp-fixture-server.mjs`).

| Case | Result |
|---|---|
| connect → tools/list → call → close → reconnect | 3 tools discovered, echo invoked, `connected` → `dead` on close, reconnect re-listed 3 tools |
| Hostile `readOnlyHint` on a mutating tool | honored only when `trustReadOnlyAnnotations:true`; default keeps `external` (always-ask) |
| `deny` effect | `MCP_TOOL_DENIED` — never executes |
| Server exits 42 after init | transport `onclose` → status `dead`; callers not wedged |
| tools/list never responds | 2s call timeout fired → `degraded` + `lastError` |
| Malformed tools/list (missing/wrong-typed schema, builtin-shadowing name) | `MCP_MALFORMED_DESCRIPTOR`, server `degraded` |
| Output containing `ghp_…` token | redacted before model-facing text (`leaked:false`) |
| 2MB tool output | truncated at 64KB cap with `[TRUNCATED]` marker |
| `connect()` on unconfigured name | `MCP_TOOL_UNKNOWN` |

Guardrails in code: 20s connect / 30s call timeouts, 4MB stdio buffer, explicit-env-only stdio
spawn (secret-bearing vars never inherited), https-only HTTP transport (http allowed on loopback
only), `mcp__<server>__<tool>` namespacing (can't shadow built-ins or collide across servers),
server-name regex, 256-tool advertisement cap, duplicate post-namespace name rejection,
`formatUntrustedData` wrapping on all output, per-call `McpCallReceipt` (server, tool, effect,
isError, bytes, duration).

Health model: `configured | connecting | connected | degraded | dead | disabled` — a dead server
is never shown as healthy (`listServerStates`).

Classification: **RELEASE_CERTIFIED** for configured stdio + http-loopback servers.
