hover:prose-a:text-mute prose-strong:text-display prose-code:text-display prose-pre:bg-panel prose-pre:border prose-pre:border-line max-w-none"><h1>Rate Limits</h1>
<p>BlockRun is a pass-through gateway: for <strong>paid</strong> model calls it does <strong>not</strong> add
its own per-request throttle. The rate limits you may hit are the <strong>upstream
provider&#x27;s</strong> capacity limits (tokens-per-minute / requests-per-minute on the
provider tier backing that model). When an upstream provider throttles a
request, BlockRun surfaces it to you transparently as an HTTP <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">429</code> so you can
back off or fail over.</p>
<div class="my-6 flex gap-3 border border-dashed border-line bg-panel p-4" style="border-left-color:#5B9BF6;border-left-width:2px;border-left-style:solid"><svg xmlns="http://www.w3.org/2000/svg" width="24" height="24" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round" class="lucide lucide-info h-5 w-5 flex-shrink-0 mt-0.5" style="color:#5B9BF6" aria-hidden="true"><circle cx="12" cy="12" r="10"></circle><path d="M12 16v-4"></path><path d="M12 8h.01"></path></svg><div class="min-w-0 text-sm leading-7 text-mute [&amp;&gt;:first-child]:mt-0 [&amp;&gt;:last-child]:mb-0"><div class="mb-1 font-normal text-display">No platform throttle on paid calls</div><p>For paid model calls there is no BlockRun-side per-request limit — your only ceiling is the upstream provider&#x27;s TPM/RPM. Free chat models are limited to <strong>30 requests/minute and 300 requests/hour per IP</strong>, and a few non-LLM endpoints (metadata catalogs, wallet reconciliation, RealFace init, onramp link minting) carry small per-IP limits to bound abuse and real upstream cost.</p></div></div>
<h2>The <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">429</code> response</h2>
<p>When an upstream provider rate-limits a request, BlockRun returns:</p>
<div class="my-6 overflow-hidden bg-panel border border-dashed border-line"><pre class="p-4 sm:p-6 overflow-x-auto text-sm leading-relaxed" node="[object Object]"><code class="hljs language-http font-mono" node="[object Object]">HTTP/1.1 429 Too Many Requests
Retry-After: 60
Content-Type: application/json
</code></pre></div>

<p>This applies to both the standard (<code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">POST /api/v1/chat/completions</code>) and Anthropic-compatible (<code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">POST /api/v1/messages</code>) endpoints, for streaming and non-streaming requests. For streaming, the <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">429</code> is returned <strong>before</strong> the first SSE byte (no partial stream is emitted).</p>
<h2>Recommended client handling</h2>
<ol class="my-6 space-y-2 list-decimal list-inside" node="[object Object]">
<li class="text-mute" node="[object Object]"><strong>Honor <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">Retry-After</code></strong> — wait the indicated seconds, then retry (exponential backoff on repeats).</li>
<li class="text-mute" node="[object Object]"><strong>Or fail over to a same-tier model from a different family</strong> — e.g. if <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">anthropic/claude-sonnet-4.6</code> is throttled, retry on <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">openai/gpt-5.5</code> or <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">google/gemini-3.1-pro</code>. Different model families draw on independent capacity pools, so a cross-family retry usually succeeds immediately.</li>
</ol>

<h2>Behind the gateway</h2>
<p>BlockRun serves each model through its own gateway and may route a single model id across multiple backing capacity pools, failing over automatically and internally. You only ever see a <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">429</code> when <strong>every</strong> backing pool for that model is exhausted — at which point backing off or failing over to another model family is the fastest path through.</p>
<h2>Free models</h2>
<p>Free chat models (<code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">&quot;billing_mode&quot;: &quot;free&quot;</code> in <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">GET /v1/models</code>) take no payment, so they are throttled per source IP: <strong>30 requests/minute</strong> and <strong>300 requests/hour</strong>. Over the limit you get <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">429</code> with <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">code: &quot;FREE_TIER_RATE_LIMITED&quot;</code>, <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">Retry-After</code>, and <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">X-RateLimit-Limit</code> / <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">X-RateLimit-Remaining</code> / <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">X-RateLimit-Reset</code> (unix ms). Paid requests from the same IP are never counted. When the free pool itself is out of capacity the code is <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">STREAM_FAILED</code> / <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">FREE_MODEL_FAILED</code> with <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">Retry-After: 30</code>.</p>
<h2>Other endpoints</h2>
<p>The metadata catalogs (<code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">GET /v1/models</code> and the image/video/audio model lists, <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">/api/pricing</code>: 100/hour per IP; <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">/api/health</code>: 60/minute), per-wallet lookups (reconciliation, portraits, RealFace status: 120/hour), <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">POST /v1/realface/init</code> (10/hour) and <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">POST /v1/onramp/token</code> (30/hour per IP, 10/hour per wallet) carry small per-IP limits to bound abuse and real upstream cost. When exceeded they return <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">429</code> with <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">{&quot;error&quot;:&quot;Rate limit exceeded&quot;}</code> and an <code class="bg-panel2 text-display px-1.5 py-0.5 text-sm font-mono" node="[object Object]">X-RateLimit-Reset</code> header (unix ms). The full table is in the <a href="/docs/api-reference/rate-limits" node="[object Object]">API reference</a>.</p>
