# R53 subagent topology and ownership

Production `resolveAdaptiveTopology` selects Coder → ForgeVerify for tiny work, Explorer → Coder → Reviewer → ForgeVerify for normal work, and two Explorers → Planner → Coder → Reviewer → ForgeVerify for complex work when capacity allows. ForgeGreen may reduce parallel exploration when measured capacity is narrow; explicit user topology is preserved. ForgeVerify remains required in every plan. These are task-characteristic and capacity decisions, not a live learned comparison of Planner value.

The eight R53 autonomous attempts all resolved to the normal topology. The completed multi-step mission used Groq for Coder and OpenRouter for Reviewer, so physical reviewer independence was achieved. The completed checkout recovery used OpenRouter for Coder and Reviewer; the receipt reports `SAME_POOL_FALLBACK` and `reviewerIndependent=false`. The original checkout and both budget-exhausted refactor attempts blocked before review; the diagnostic refactor was cancelled before review. All eight receipts report zero duplicate tool work in worker telemetry; no pair of live Coders was dispatched against one edit scope. The `duplicate-suppression` regression suite separately proves state-bound read replay, steer/edit invalidation, workstream isolation, failed-read bounds, and no mutation suppression.

This is evidence of bounded ownership in the exercised normal topology. It does not prove the requested parallel-explorer duplicate rate or a live Planner benefit for a large feature. A live complex-topology comparison is still required to establish those claims.
