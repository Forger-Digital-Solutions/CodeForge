| LEG-P0-01 / ENG-P0-01 | Missing root LICENSE | `MITIGATED` → `BLOCKED_BUSINESS_DECISION` | MIT license *type* is already consistently declared (root `package.json`, `README.md`, `CONTRIBUTING.md`) with zero conflicting statements, so [`LICENSE.pending`](../../../LICENSE.pending) carries the canonical, unmodified MIT text ready to activate. | LEG-P0-02 / ENG-P0-02 | Cloud account deletion deficit (GDPR Art. 17) | `FIXED` | `DELETE /v1/account` in [`apps/cloud-api/src/server.ts`](../../../apps/cloud-api/src/server.ts), Bearer-only, userId sourced only from the verified token (no confused-deputy vector), gated by an explicit `{"confirmation":"DELETE_MY_ACCOUNT"}` body. Coordinator [`apps/cloud-api/src/account-deletion.ts`](../../../apps/cloud-api/src/account-deletion.ts) purges hosted-workflow session data (`@codeforge/sessions`, including the `events` table which has no FK/cascade — a real gap the schema research surfaced and this milestone closed by adding `deleteEventsForSession`) before running `ICloudDatabase.deleteUserAccount()`, a single transaction (`withTx` on Postgres; explicit BEGIN/COMMIT/ROLLBACK on SQLite, since SQLite does not enforce `ON DELETE CASCADE` unless a pragma this codebase doesn't set is on) that explicitly deletes every one of the 16 linked tables plus anonymizes (not deletes — see retention below) `abuse_events.user_id`. Idempotent by construction (retry is a safe no-op). Tested: `packages/cloud-db/test/account-deletion.test.ts` (SQLite + **real PostgreSQL**, proving cascade-equivalent completeness, cross-user isolation, and transactional rollback against a live server), `apps/cloud-api/test/account-deletion.test.ts` (unauthenticated rejection, missing-confirmation rejection, cross-user impossibility, full HTTP round-trip incl. hosted-session deletion, idempotent retry). Desktop UI: `Settings → Legal → Account & Deletion` and a two-step confirmation "Danger Zone" in the Cloud Account modal, live-verified in a real Electron capture harness (see report). |
| LEG-P0-03 / ENG-P0-03 | EEA regional ban on unpaid Gemini hosted routing | `FIXED` | `@codeforge/legal-policy`'s `evaluateRouteEligibility()` gate, wired into `CloudFirewallManager.checkProviderPolicy()` and `GatewayService.executeHostedInference()` *before* ForgeZero's financial verification. Deliberately **not** naive `cf-ipcountry` GeoIP (R1 spec §11 overrides Pass-3's original suggestion): region evidence is accepted only from a deployment-configured, explicitly-documented trusted header (`CODEFORGE_TRUSTED_REGION_HEADER`, unset by default); with no trusted source configured, hosted Gemini-unpaid resolves `REGION_UNKNOWN` and **fails closed** (`PROVIDER_POLICY_REGION_UNKNOWN_FAIL_CLOSED`). Auto-routing gracefully falls back to the next ranked, policy-eligible candidate (e.g. Groq) instead of failing the whole task, using the router's own `alternatives` list — no shared `packages/router`/`forge-zero` code was touched, so Desktop BYOK is provably unaffected. Desktop Gemini BYOK in the EEA is explicitly represented as `attorneyReviewStatus: "PENDING"` (Q1 of the attorney packet), not auto-blocked, per R1 spec §13. Tested end-to-end in `packages/cloud-gateway/test/provider-region-policy.test.ts` (denied region, unknown region, allowed region, BYOK unaffected, graceful auto-fallback, no paid fallback). |
